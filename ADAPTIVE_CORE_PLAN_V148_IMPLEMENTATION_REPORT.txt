ビービー Ver148 Adaptive Core Plan 実装結果

対象:
- ビービー Ver145 AdaptiveCorePlan初期実装 全部入り

適用した正本:
- ビービー Ver142 マスター作業指示書 Adaptive Core Plan 深掘り版 v148

主な実装:
1. 新UIのSELF_IMPROVEMENT + TYPED_IMPROVEMENT_UI_GATEWAYを固定3RouteではなくAdaptive Plan分岐へ変更。
2. Core側にImprovement Readinessを構造化し、issue/context/target/evidence/knowledge/capability/candidate/validation/packageの状態から次Operationを選択。
3. Candidate生成前にRepository Context/Target/Evidence/未解決状態を確認。
4. Candidate成功後のみValidationを選択し、Candidate識別情報を引継ぎ。
5. Validation成功後のみReview Packageを選択し、Candidate/Validation識別情報を引継ぎ。
6. dependsOnをCommand名ではなくoperationInstanceIdで拘束。
7. 同一Domainの再訪をvisitedDomainsで抑止せず、失敗時は新しいOperation Instanceを作れるよう変更。
8. target:command単位の重複排除とroutes.slice(0,3)によるRequired Operation消失を撤去。
9. Core Plan Revisionが過去に成功したOperationを新Revisionでも保持できるよう変更。失敗した旧Operationは新しい同種Operation追加時にSUPERSEDED化。
10. Candidate Workspace保存に永続化Receiptを追加。
11. Review Package Ledger保存にも永続化Receiptを追加。
12. Domain Reply Ledgerがnested persistence receiptを回収できるよう変更。
13. Candidate ValidationをCandidate manifest hash単位に統一。
14. Review PackageへcandidateId / validationBundleId / learningLineage / externalReviewQuestionsを引継ぎ。
15. 新UIの主要ステータス表示ではTask/Plan/Operation IDを前面に出さず、現在工程と次工程を表示。
16. Adaptive Plan専用のVer148接続試験を追加し、既存Ver145試験も新設計に合わせて更新。
17. UIから直接Candidate生成へ進む場合でもCore TaskとImprovement Runを同一Task系譜で確立できるensureForCoreTaskを追加。
