基準日: 2026-09-18
対象: 新UI / 会話 / 自己コード改善

【重要】
17分類が存在することだけを合格条件にしていない。
新UIからCOREへ入り、COREがBlackboardを評価して必要な分類を選択し、Domain ResultをCOREへ戻し、COREが再評価することを確認対象とした。

【会話】
修正前は App.tsx の通常チャットが mikiCategoryInteractionRuntime.requestInteraction('conversation.request', ...) を直接起点としており、CORE Orchestrator のAdaptive Planを会話の入口としていなかった。

修正:
- App.tsx の通常チャット入口を typedCoreUiGatewayService.submitConversation() に変更。
- submitConversation() は CoreTaskIngressService → CoreOrchestratorService に投入。
- payload.entry=TYPED_CONVERSATION_UI_GATEWAY を付与。
- AdaptiveRoutePlanner に会話専用の状態判断を追加。
- conversation.ANALYZE_TEXT をCOREが必要時に選択。
- 未知/検索系ではunknown、明示的なknowledge gapが残ればresearchをCOREが追加選択。
- Domain ResultをCOREが収集・再評価。
- 実際の回答生成後、typedCoreUiGatewayService.finalizeConversationResponse() → CoreOrchestratorService が最終CoreResultをcompletedへ確定。
- autonomous_rule の非LLM会話経路も同じCORE最終確定を使用。

【自己コード改善】
- SelfCodeArchitectTab / EvidenceBasedLoopSubView / AutonomousImprovementSettingsPanel / NonLlmArchitectureTab / チャット自己改善入口はtypedImprovementUiGatewayServiceを使用。
- Gateway → CoreTaskIngress → CoreOrchestrator → AdaptiveRoutePlanner。
- readiness不足時にassessment/research/unknown/capability/selfDevelopment等をCOREが状態に応じて選択。
- Candidate成功前にValidationを発行しない。
- Validation成功前にReview Packageを発行しない。
- Candidate identity / operationInstanceId / planRevision / persistence receiptを後続へ継承。
- Review PackageはreviewZipExportServiceで凍結Snapshotから生成・検証。
- ReviewPackageLibraryはtypedCoreUiGatewayService経由でLedger一覧、再生成、ZIP保存を実行。
- ZIP生成後にdownload可能。
