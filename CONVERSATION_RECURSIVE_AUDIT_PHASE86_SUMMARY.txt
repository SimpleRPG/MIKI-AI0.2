- Two different ClaimDatabaseService implementations existed and legacy services imported the older src/services copy. This could create divergent in-memory Claim maps even though both used the same storage key. The legacy path is now a compatibility re-export of the canonical miki/memory authority. Runtime identity E2E confirmed both imports return the same singleton.
- formalSemanticsKernelService already uses the correct compatibility re-export pattern; no parallel authority remained there.
- semanticContextBudgetService is implemented and behaves correctly but has no direct production importer. It remains a confirmed unconnected capability.
- Existing anaphora modules are connected through conversationStateService. They are not orphaned.
- The old conversation-learning regression conflicts with the later safety rule that repeated USER_CLAIM affirmation is not independent evidence. The runtime safety rule is retained.
