MIKI-AI0.2 SearXNG -> 内容読取 統合修正レポート
Version: Ver153
Date: 2026-09-18

【目的】
SearXNGを単なる検索入口で終わらせず、ResearchServiceの研究経路から検索結果URLを実際に読み、ページ内容をWeb Evidenceとして取得するところまで一本化する。

【仕様書確認】
今回の修正前に以下の設計資料を確認した。
- 非LLM中心_自己成長型AIコンパニオン_設計思想指示書_統合版.md
- MIKI-AI0.2_SEARXNG_IMPLEMENTATION_SUMMARY_2026-09-18.txt
- ビービー_Ver142_マスター作業指示書_AdaptiveCorePlan深掘り_v148.txt

仕様上の要点:
- 調査は「読む」ことを含む。
- 検索エンジンだけでなく公式資料、API、サンプル、ソース、テスト、Issue、リリースノート、Web資料等を課題に応じて読む。
- SearXNGは新しい分類ではなくresearch等から利用する内部探索手段。
- 検索結果はEvidenceとして扱い、検索だけではKnowledge Gapを解決しない。
- Evidence -> Claim -> Verification -> Knowledge Gap解決の境界を維持する。

【今回の修正】
1. src/miki/research/services/autonomousSearchService.ts
   - readSearchResultPages() を追加。
   - Researchから渡された検索結果URLのうちhttp/httpsの結果を最大3件（既定2件）まで実際に読む。
   - nativeWorkManagerService.fetchRenderedPage() を利用するため、Android NativeではヘッドレスWebView、Web/Nodeでは既存fetch+HTMLテキスト抽出フォールバックを使用する。
   - 読み取り失敗時は検索結果を捨てず、ページEvidenceだけを追加しないfail-soft動作。

2. src/miki/research/services/researchService.ts
   - executeSearch() 後に readSearchResultPages() を必ず呼ぶWEB_SEARCH研究経路へ変更。
   - ページ本文を最大12,000文字までWeb Evidenceとして記録。
   - providerがSearXNGの場合はprovider='searxng'として記録し、取得方法をfetch_method='headless_webview'としてEvidence metadataへ保存。
   - ページ本文そのものを確定知識にはせず、Claimは引き続き未検証状態から開始し、昇格はverifierServiceに限定。
   - 元の検索スニペットEvidenceも残すため、検索発見と本文読取の両方を監査可能。

3. src/miki/memory/services/evidenceService.ts
   - Evidence metadataにfetch_methodを追加し、本文読取の取得経路を保持できるようにした。

4. scripts/verify_searxng_content_read_pipeline_v153.mjs
   - SearXNG検索 -> URL -> fetchRenderedPage -> Research Evidenceの接続を静的に検査する専用テストを追加。

5. package.json
   - test:searxng-content-read-v153 を追加。

【最終経路】
UI / CORE
  -> research
  -> autonomousSearchService.executeSearch()
  -> SearXNG / fallback provider
  -> 検索結果URL
  -> autonomousSearchService.readSearchResultPages()
  -> nativeWorkManagerService.fetchRenderedPage()
  -> Web Evidence
  -> Claim
  -> verifierService
  -> Cognitive Evidence Integration / Knowledge Gap
  -> CORE Result
