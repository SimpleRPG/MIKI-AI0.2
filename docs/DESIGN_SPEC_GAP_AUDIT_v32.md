# MIKI-AI0.2 設計思想指示書 適合監査 v32

## 目的

v31時点の実装を、`非LLM中心_自己成長型AIコンパニオン_設計思想指示書_統合版.md` の19章完成条件と18章ロードマップを基準に監査する。

## 重要な結論

「サービスが存在する」ことと「設計思想の完成条件を満たす」ことは別である。v31は基盤サービスの数は多いが、未接続・自己証明・実機証拠不足の領域が残る。

## 特に危険な未達

1. **自己証明:** 合成カリキュラムの自己採点だけで能力を卒業扱いしてはいけない。v32で `SELF_SIMULATED` と `EXTERNALLY_VERIFIED` を分離。
2. **判断の架空スコア:** 根拠なしの固定点で推薦しない。v32で同点/根拠不足を未確定化。
3. **実機証拠:** DEVICE_TESTED/VERIFIEDはAndroid/Excel実機の実測なしには成立しない。
4. **物理部品正本:** 現在のArtifact Storeは論理的な永続化であり、設計書のTXT正本運用そのものではない。
5. **自律改善の最後の一歩:** 候補生成→Regressionまでは進んだが、改善採用後の本番影響比較・ロールバックまでの連続E2Eが不足。

## 次の実装優先順位

### P0-1 日本語解析基盤
形態素解析Providerを抽象化し、Androidで利用できる実装とフォールバックを明示。個人辞書・語義ID・用例を会話状態/検索へ接続する。

### P0-2 物理TXT部品正本
`component.txt / implementation.txt / tests.txt / validation.txt / sources.txt / history.txt` の役割を実ファイルとして固定し、SQLiteは索引・メタデータに限定する。

### P0-3 実行証拠の閉ループ
Android Native Runner/Excel External Runnerの実測結果を、Regression→Promotion→Case Memory→Decision Learningへ一貫接続する。

### P0-4 自己改善の採用ゲート
Hardening FAIL→Regression Test→実測→Before/After比較→Canary→Rollback→Stableの順を固定し、自己評価だけでは採用不可にする。

### P0-5 Android常駐E2E
WorkManager、Native Runner、Storage、通知、音声の実機検証をGitHub ActionsのAPK生成後に行う。

## v32での追加修正

- 判断の初期評価を `PENDING` に変更し、判断確定と結果成功を混同しない。
- 根拠なしの架空50/51点による自動推薦を廃止。
- 同点を勝者にしない。
- 自律カリキュラムの自己シミュレーションを正式検証から分離。
- 外部証拠IDを持つ正式検証APIを追加。
- 自己改善メトリクスの実行イベントを永続化し、再起動後も直近24時間の測定を継続可能にした。

## 完成条件との関係

19章の完成条件は、コード上のサービス存在だけでは満たさない。最終判定にはAndroid実機、必要に応じてExcel PC、実データ、回帰試験、実行ログを用いた証拠が必要である。
